# Architecture

## Обзор

`appmetrica-cli` — read-only аналитика AppMetrica. Устроен как CLI-first: общее ядро (`service.py`) не знает о способе вызова, а интерфейсов два — терминал (`appmetrica <команда>`) и MCP-сервер (`appmetrica mcp`). MCP-сервер — тонкий адаптер: Reporting-тулы вызывают `client.py` напрямую, локальные — `service.py`.

Данные Logs API складываются в Parquet-партиции (по одной на таблицу и день приёма). Из них команда `build` пересобирает DuckDB-базу `analytics.duckdb`; по ней считаются ежедневные метрики, retention, воронки, IAP/ad revenue, SQL-запросы и обзор событий. Reporting API используется для онлайн-отчётов и для сверки A1, Logs API — для загрузки сырых данных.

```
   терминал                          MCP-клиент
 appmetrica <cmd>              (Claude Code / Desktop / Cursor)
        │                                    │ MCP (stdio)
        ▼                                    ▼
   ┌──────────┐                       ┌────────────┐
   │ cli.py   │                       │ server.py  │
   │ (click)  │                       │ (FastMCP)  │
   └────┬─────┘                       └─────┬──────┘
        │                                   │
        └────────────────┬──────────────────┘
                         ▼
                  ┌──────────────┐
                  │ service.py   │  общее ядро
                  └──┬───┬───┬───┘
      ┌──────────────┘   │   └───────────────┐
      ▼                  ▼                   ▼
┌────────────┐   ┌──────────────┐   ┌──────────────────┐
│ client.py  │   │ loader.py +  │   │ report.py        │
│ HTTP .com  │   │ storage.py   │   │ funnel.py        │
│ и .ru      │   │ → Parquet    │   │ sandbox.py       │
└─────┬──────┘   └──────┬───────┘   │ discover.py      │
      │                 │ build()   │ fx.py (ECB)      │
      ▼                 ▼           └────────┬─────────┘
AppMetrica API    analytics.duckdb           │
                         └────► db.py ◄──────┘
                            (read-only)
```

Reporting-тулы `server.py` идут в API через клиент, созданный в lifespan, минуя `service.py`; команды `sync` и `reconcile` создают клиент внутри сервиса, а `loader.py` пользуется им при выгрузке.

## Модули

### auth.py
Токен OAuth: источники, порядок выбора, проверки.

- `APPMETRICA_OAUTH_TOKEN` (env) либо `APPMETRICA_OAUTH_TOKEN_FILE` (файл); задавать оба одновременно нельзя.
- Иначе — системное хранилище, зафиксированное по платформе: macOS Keychain, Windows Credential Manager с `persist="local machine"`, Linux Secret Service. Глобальный выбор бэкенда keyring (`PYTHON_KEYRING_BACKEND`, `keyringrc.cfg`) не используется; любой `KEYRING_PROPERTY_*` приводит к отказу с кодом 4.
- Токен-файл не поддерживается на Windows. На остальных платформах он открывается через `O_RDONLY | O_NONBLOCK | O_CLOEXEC`, и все проверки делаются по `fstat` уже открытого дескриптора: обычный файл, владелец — текущий euid, `mode & 077 == 0`, размер не больше 4096 байт. Токен читается из этого же дескриптора, декодируется строго как ASCII.
- Токен: 1–1024 печатных ASCII-символа без пробелов. Plaintext-фолбэка нет: если системного хранилища нет, команда завершается с кодом 3 до любого сетевого вызова.
- Коды выхода: 2 — API отклонил токен, 3 — хранилище недоступно или его ошибка, 4 — ошибка конфигурации.
- Сообщения об ошибках не содержат токен: только фиксированный текст, имена переменных, пути и классы исключений.

### config.py
`AppMetricaConfig.from_env()` собирает frozen dataclass: токен через `auth.get_token()`, базовые URL Management (.com) и Reporting/Logs (.ru), язык ответов, таймаут запроса 30 с, интервал опроса Logs API 10 с, общий таймаут опроса 300 с, параметры retry. Поле токена исключено из `repr`. `home_dir()` возвращает `APPMETRICA_HOME` или `~/.appmetrica-cli`.

### client.py
Асинхронный HTTP-клиент поверх `httpx.AsyncClient`.

- Management API (.com): `list_applications()`.
- Reporting API (.ru): `get_report()` на `/stat/v1/data` и `get_drilldown()` на `/stat/v1/data/drilldown`; JSON-эндпоинты Logs API не работают (404), выгрузка идёт только через CSV.
- Logs API (.ru): `export_logs_csv()` на `/logs/v1/export/{table}.csv` с `date_dimension=receive`, `skip_unavailable_shards=false`, `use_utf8_bom=false`, `fields` из фиксированного каталога таблиц. Ответ 202 опрашивается каждые 10 с до 200 либо до таймаута 300 с (тогда `AppMetricaError` 408); `active_exports()` читает `get_active_queries` и возвращает экспорты со статусом 0.
- Повторы: транспортные ошибки, а также коды 420, 429, 500, 502, 503, 504 — до 3 повторов с экспоненциальной задержкой; `Retry-After` учитывается, но не больше 60 с. Остальные коды сразу превращаются в `AppMetricaError(status_code, message, endpoint)`.

### loader.py
Синхронизация Logs API в хранилище.

- Партиция = (таблица, день приёма D в часовом поясе приложения). Окно запроса — `D 00:00:00`–`D 23:59:59` в этом поясе, `date_dimension=receive`.
- Часовой пояс берётся из `time_zone_name` приложения в Management API и проверяется через `ZoneInfo`; смена пояса у приложения делает старые партиции невалидными, поэтому синхронизация останавливается с требованием удалить каталог приложения.
- День считается закрытым, если партиция выгружена не раньше чем через 24 часа после конца D. Каждая синхронизация заново выгружает отсутствующие и незакрытые дни, а также последние 7 дней; дни позже сегодняшнего в поясе приложения не запрашиваются.
- Перед каждым экспортом проверяется очередь незавершённых экспортов приложения. Если очередь не пуста, синхронизация останавливается с отчётом: новые запросы не встают за зависшим.
- Ошибка API останавливает проход; уже записанные партиции остаются. `requested_at` фиксируется до запроса, чтобы отметка `fetched_at` не была позже фактически полученных данных.

### storage.py
`AppStore` — локальное хранилище и пересборка аналитической базы.

- Layout: `<home>/apps/<app_id>/<table>/day=YYYY-MM-DD.parquet`, `<home>/apps/<app_id>/state.json`, `<home>/apps/<app_id>/analytics.duckdb`.
- Таблицы: `events`, `installations`, `sessions_starts`, `revenue_events`, `ad_revenue_events`. Набор полей каждой таблицы фиксирован; CSV-заголовок ответа обязан совпасть с запрошенными полями, иначе партиция не пишется.
- Все значения хранятся строками ровно в том виде, в каком их вернул API; IP-колонки не запрашиваются. Строки сортируются по всем колонкам, Parquet пишется с фиксированными настройками (zstd, `ROW_GROUP_SIZE 122880`), поэтому одинаковые данные дают одинаковые байты.
- `state.json`: часовой пояс приложения и `fetched_at` (UTC) по каждой таблице и дню. Запись атомарная (временный файл + `os.replace`), состояние обновляется после файла партиции: сбой между ними даёт повторную выгрузку, но не ложную отметку «закрыт».
- `build()` пересобирает `analytics.duckdb` из всех партиций и публикует его атомарно. В каждой таблице, кроме исходных строковых колонок:
  - `ts_device_utc`, `ts_receive_utc` — время устройства и время приёма как TIMESTAMP в UTC;
  - `ts_utc` — эффективное время (D2): время устройства, если оно не больше чем на 5 минут впереди и не больше чем на 7 дней позади времени приёма; иначе время приёма;
  - `time_fixed` — признак, что время приёма заменило время устройства;
  - `day` — день `ts_utc` в часовом поясе приложения, `receive_day` — день `ts_receive_utc` в нём же.
- В базу также пишется `app_meta(app_id, time_zone)`.

### db.py
Read-only подключение к `analytics.duckdb`. Если база не собрана, выбрасывается `StorageError` с указанием сначала выполнить build.

### report.py
Метрики по колонке `day` (эффективное время в поясе приложения).

- DAU — число различных `appmetrica_device_id` с событием или стартом сессии в этот день.
- Sessions — строки `sessions_starts` за день, точные дубликаты считаются один раз.
- Installs — строки `installations` с `is_reinstallation = 'false'`, точные дубликаты считаются один раз.
- Retention D-N — когорта не-реинсталлов дня; возврат — активность (событие или старт сессии) ровно в день `day + N`. Если `day + N` позже последнего дня, присутствующего в загруженных events/sessions_starts/installations, когорта для этого N не считается и попадает в `immature`.
- IAP — строки `revenue_events`: валюта нормализуется в верхний регистр, цена разбирается как `Decimal`. Строки без валюты или с неразбираемой ценой попадают в бакет `invalid`, с количеством не равным 1 — в `quantity`, без курса — в `no_fx`. Остальные суммируются в USD с округлением до 0.01 (`ROUND_HALF_UP`).
- Ad revenue — суммы `ad_revenue` по дням и исходным валютам, без конвертации; опционально с разбивкой по сети.

### funnel.py
Воронка на уровне устройства по таблице `events`.

- Шаг задаётся точным `event_name` и точными значениями параметров первого уровня `event_json`; сравнение через `json_extract_string`, JSON в Python не парсится.
- Устройство входит в воронку по своему первому событию шага 1. Каждый следующий шаг должен произойти строго после предыдущего и не позже входа плюс окно; окно отсчитывается от входа, а не между шагами.
- Точные дубликаты строк считаются один раз. Повтор шага `[A, A]` требует двух разных вхождений с разными отметками времени.
- Вход, у которого вход плюс окно позже последнего `ts_utc` в загруженных событиях, исключается из конверсий и считается отдельно (`immature_entries`).
- `parse_window` разбирает `Nd`, `Nh`, `Nm`, `Ns`.

### sandbox.py
Песочница произвольного SQL над `analytics.duckdb`.

- Принимается ровно один оператор `SELECT`/`WITH`: проверяется первое ключевое слово (с учётом комментариев), затем `duckdb.extract_statements` и тип оператора. `PRAGMA` отсекается по первому слову, потому что DuckDB внутренне переписывает его в SELECT.
- Соединение read-only с настройками `enable_external_access=false`, `lock_configuration=true`, `memory_limit=1GB`, `threads=2`: запрос не может читать файлы, подключать базы или менять конфигурацию.
- Таймаут по умолчанию 60 с: таймер прерывает выполнение через `interrupt()`. Результат ограничен 10 000 строк, флаг `truncated` показывает усечение.
- Ошибки открытия базы не пересылаются как есть, чтобы не раскрывать пути; сообщения содержат только SQL пользователя и текст ошибки DuckDB.

### discover.py
Обзор загруженных данных без знания конкретных имён событий.

- `list_events()` — непустые имена событий с числом строк, числом устройств и первым/последним днём.
- `event_parameters()` — ключи первого уровня `event_json`, типы значений (`json_type`) и топ-10 значений (`json_extract_string`); JSON обрабатывается только средствами DuckDB.

### fx.py
Курсы ECB для IAP.

- Скачивается `eurofxref-hist.zip`; в архиве принимается CSV или XML. Курсы хранятся как единицы валюты за 1 EUR.
- Дисковый кэш: `<home>/fx/eurofxref-hist.zip` и `meta.json` с датой загрузки. Кэш считается достаточным, если в нём есть публикация строго раньше первого нужного дня и либо покрыт последний нужный день, либо архив скачан не раньше него. Испорченный кэш заменяется повторной загрузкой.
- Курс дня — последняя публикация строго до этого дня, поэтому выходные и праздники используют предыдущий рабочий день. USD равен 1; EUR переводится через курс USD/EUR, остальные валюты — кросс-курсом через EUR.
- Сетевые ошибки, пустой и некорректный архив дают `FxError`; пустая таблица молча не возвращается.

### service.py
Общее ядро для CLI и MCP. Аналитики здесь нет: только оркестрация.

- `sync_app()` — сетевой проход `loader.sync` с клиентом из конфигурации.
- `build_app()` — пересборка `analytics.duckdb`.
- Локальные отчёты: `daily_report`, `retention_report`, `ad_report`, `funnel_report`, `sql_query`, `events_overview`, `event_params` — открывают базу и вызывают report/funnel/sandbox/discover.
- `iap_report()` — определяет нужные дни по `revenue_events`, при необходимости догружает курсы ECB и считает IAP.
- `reconcile_a1()` — сверка локальных DAU, sessions и installs с Reporting API ровно двумя запросами: `ym:ge:users` + `ym:ge:sessions` по `ym:ge:date` и `ym:i:installDevices` по `ym:i:date`. Расхождение возвращается как данные, а не исключение.

### cli.py
Click-группа `appmetrica`: `auth login|status|logout`, `sync`, `build`, `report`, `retention`, `revenue`, `funnel`, `sql`, `events`, `reconcile`, `mcp`.

- Команды данных и auth печатают JSON; `mcp` запускает сервер по stdio. Ошибки уходят в stderr с ненулевым кодом выхода.
- `auth login` проверяет токен запросом к API до записи в хранилище; хранилище требуется до сетевого вызова. `--stdin` читает токен сырыми байтами.
- Локальные команды (`build`, `report`, `retention`, `revenue`, `funnel`, `sql`, `events`) не требуют токена AppMetrica. `revenue` может скачать курсы ECB, но токен ему не нужен. `sync` и `reconcile` требуют токен.
- По умолчанию диапазон — последние 7 дней включительно (UTC-даты); `sync` принимает `--tables`, неизвестная таблица отклоняется.
- `main` выставляет `umask 077`.

### server.py
FastMCP-сервер «AppMetrica Analytics». Lifespan создаёт конфигурацию, `httpx.AsyncClient` и `AppMetricaClient`, разделяемые Reporting-тулами.

- 9 Reporting-тулов: `get_report`, `get_drilldown` и 7 пресетов — `get_traffic`, `get_installs`, `get_crashes`, `get_geo`, `get_events`, `get_devices`, `get_versions`.
- 11 локальных тулов: `sync`, `build`, `get_daily_metrics`, `get_retention`, `get_iap_revenue`, `get_ad_revenue`, `build_funnel`, `run_sql`, `list_events`, `explore_event_params`, `reconcile`.
- 2 discovery-тула: `list_apps` (Management API) и `list_metrics` (статический каталог `metrics.py`).
- Все тулы помечены `readOnlyHint=True`. Ошибки возвращаются словарём `{"error": ..., "status_code": ...}`, а не выбрасываются наружу.
- 2 prompt-шаблона: `daily_analytics_check`, `compare_periods`.

### metrics.py
Каталог Reporting API. В `METRICS` и `DIMENSIONS` только имена, принятые живым API (E-038/E-040). В одном запросе метрики и измерения должны иметь один префикс (`ym:ge:`, `ym:s:`, `ym:ce:`, `ym:cr:`, `ym:i:`); смешивать префиксы можно только в фильтрах. Retention и revenue через Reporting API недоступны и считаются локально. Семь пресетов: `traffic`, `installs`, `crashes`, `geo`, `events_top`, `devices`, `versions`; `resolve_dimensions` проверяет допустимый `group_by`, `combine_filters` соединяет фильтры через AND с обёрткой в скобки, `quote_value` экранирует литерал.

## Потоки данных

### Sync → build → локальные отчёты

```
appmetrica sync --app N [--from D --to D] [--tables ...]
  → loader.sync: для каждой таблицы и дня D
      → client.active_exports: очередь не пуста → остановка
      → client.export_logs_csv(D 00:00:00–23:59:59, date_dimension=receive)
      → storage.write_partition: CSV → Parquet (замена целиком) → state.json

appmetrica build --app N
  → storage.build: все партиции → analytics.duckdb (сырые и вычисляемые колонки, app_meta)

appmetrica report|retention|revenue|funnel|sql|events
  → service → report/funnel/sandbox/discover → db.read_only(analytics.duckdb)
```

В MCP те же шаги доступны тулами `sync`, `build`, `get_daily_metrics`, `get_retention`, `get_iap_revenue`, `get_ad_revenue`, `build_funnel`, `run_sql`, `list_events`, `explore_event_params`: локальные тулы работают по уже собранной базе и не ходят в AppMetrica.

### Reconcile A1

```
appmetrica reconcile --app N --from D --to D
  → report.daily_metrics (локально)
  → Reporting API: 1) ym:ge:users, ym:ge:sessions × ym:ge:date
                   2) ym:i:installDevices × ym:i:date
  → построчное сравнение ours / appmetrica / diff; matched_days, mismatched_days
```

День, которого нет на одной стороне, остаётся строкой сравнения с `null`; расхождение не является ошибкой выполнения.

### IAP и ECB

```
service.iap_report
  → report.iap_days: дни с revenue_events в диапазоне
  → fx.load_fx: кэш <home>/fx/ достаточен? да → использовать; нет → скачать eurofxref-hist.zip
  → report.iap_revenue: для каждой строки
      quantity ≠ 1            → бакет quantity
      валюта/цена некорректны → бакет invalid
      нет курса               → бакет no_fx
      иначе                   → events += 1, gross_usd += price × курс(день − строго раньше)
```

Ad revenue считается отдельно: сырые суммы по исходной валюте, без курса и без сети.

## Решения и trade-offs

| Решение | Почему | Компромисс |
|---------|--------|------------|
| Эффективное время D2 (`ts_utc`) | Время устройства сохраняет его часовой пояс и точность, но часы могут врать. Отсечка «больше 5 минут впереди или больше 7 дней позади времени приёма» отбрасывает явный сдвиг, оставляя нормальные задержки офлайна | Время приёма — грубее; время устройства без отсечки искажает день |
| Партиции по дню приёма в поясе приложения | Logs API партиционирует по `receive`, поэтому границы запроса стабильны и не зависят от поздних событий | День события и день приёма — разные колонки; отчёты используют вычисленный `day` |
| Whole-partition replace вместо дедупликации | Перезапись целого дня идемпотентна и не требует первичного ключа; повторный sync не плодит дубликаты | День, уже закрытый, повторно не читается, кроме последних 7 дней; поздние данные за пределами окна не подхватываются |
| «Закрытый» день = выгружен ≥ 24 ч после конца дня | Даёт API время дописать строки, не читая день на каждом sync | Порог — допущение; окно обновления в 7 дней страхует задержки |
| Курс строго до дня события | Нет заглядывания вперёд; совпадает с публикацией ECB и даёт одинаковый результат при повторном расчёте | Курс самого дня не используется; для валюты без курса строка уходит в `no_fx`, а не в приблизительную сумму |
| USD = 1 без обращения к таблице | Курс ECB задан через EUR, а USD — базовая валюта отчёта | Для остальных валют нужна публикация до дня события |
| Песочница read-only + `lock_configuration` | Пользовательский SQL не должен читать файлы, подключать базы или менять настройки; таймаут и лимит строк ограничивают стоимость запроса | Полноценный SQL по базе доступен, но без внешних источников и записи |
| Parquet — источник истины, DuckDB пересобирается | Партиции неизменяемы и переносимы, `analytics.duckdb` можно удалить и собрать заново; публикация атомарная | После sync нужен build; аналитика всегда идёт по снимку на момент сборки |
| Горизонт незрелости = горизонт загруженных данных | Retention и воронка не предполагают полноту данных за пределами загруженного; незрелые когорты и входы показываются отдельно | Если sync отстаёт от текущей даты, часть когорт считается незрелой |
| Reporting API не кэшируется | Онлайн-отчёты уже быстрые; тяжёлые вычисления идут по локальной базе | Каждый Reporting-запрос — сетевой вызов в пределах rate limit |

## Безопасность

- **Токен.** Хранится только в системном хранилище ОС; альтернативы — env или защищённый файл. Plaintext-фолбэка нет, перенаправление keyring запрещено, ошибки и `repr` конфигурации токен не содержат. Файл токена проверяется по открытому дескриптору (тип, владелец, права, размер), а не по пути.
- **Read-only.** Клиент делает только GET; write-API AppMetrica не используются. `analytics.duckdb` открывается с `read_only=True`. Песочница дополнительно запрещает внешний доступ и фиксирует конфигурацию.
- **SQL.** Значения передаются параметрами `?`; имена таблиц и колонок берутся из фиксированного каталога `TABLES` и цитируются. Произвольный SQL песочницы ограничен одним SELECT/WITH, read-only-соединением, таймаутом и лимитом строк; сообщения об ошибках не раскрывают пути и настройки.
- **Файлы.** CLI выставляет `umask 077`; партиции, состояние и аналитическая база публикуются через временный файл и `os.replace`, чтобы не оставлять частично записанных артефактов.

# Установка и первый отчёт: пошаговый гайд

Это инструкция для тех, кто не работает с командной строкой каждый день. До первого отчёта — примерно 15 минут. Все команды выполняются в терминале (на macOS: Программы → Утилиты → Терминал; на Windows: PowerShell).

> **macOS и стоит Homebrew?** Можно короче: `brew install ampersante/tap/appmetrica-cli` — и пропустите шаги 1–3. Во всех командах ниже пишите `appmetrica` вместо `uv run appmetrica`.

Если что-то пошло не так — см. раздел «Частые проблемы» в конце.

## Что понадобится

- Компьютер с macOS, Windows или Linux.
- Аккаунт в [AppMetrica](https://appmetrica.yandex.com/), у которого есть доступ к вашему приложению (право на просмотр отчётов).
- 15 минут времени.

Все команды ниже начинаются со слова `uv run appmetrica …` — это и есть работа с инструментом.

## Шаг 1. Установить uv

uv — это менеджер Python-окружения, через него работает наш инструмент.

**macOS** — выполните в терминале:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

(или, если у вас есть Homebrew: `brew install uv`)

**Windows (PowerShell):**

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

**Linux** — та же команда, что для macOS (`curl … | sh`).

После установки закройте и снова откройте терминал, затем проверьте:

```bash
uv --version
```

Должно напечататься что-то вроде `uv 0.9.x`.

## Шаг 2. Скачать проект

**Вариант А — через git** (если git установлен):

```bash
git clone https://github.com/ampersante/appmetrica-cli.git
cd appmetrica-cli
```

**Вариант Б — без git:** откройте страницу проекта на GitHub, нажмите зелёную кнопку **Code** → **Download ZIP**, распакуйте архив, затем в терминале перейдите в распакованную папку:

```bash
cd путь/к/папке/appmetrica-cli
```

## Шаг 3. Установить зависимости

В папке проекта выполните:

```bash
uv sync
```

Команда скачает Python и все нужные библиотеки — это занимает пару минут. Ошибок быть не должно; если они появились, проверьте интернет и повторите.

## Шаг 4. Получить токен AppMetrica

Токен — это длинная строка из букв и цифр, «ключ доступа». Инструмент читает данные из AppMetrica только для чтения; токен нужен, чтобы AppMetrica понимала, чьи данные можно показывать. Обращайтесь с ним как с паролем.

1. Откройте [oauth.yandex.com/client/new](https://oauth.yandex.com/client/new) в браузере, где вы вошли в аккаунт Яндекса с доступом к AppMetrica.
2. Создайте приложение (кнопка создания) и выдайте ему право **`appmetrica:read`** — доступ к AppMetrica только на чтение.
3. Пройдите показанные шаги и получите токен. Скопируйте его в надёжное место.

## Шаг 5. Сохранить токен

```bash
uv run appmetrica auth login
```

Появится запрос `AppMetrica OAuth token:` — вставьте токен (ввод не отображается — это нормально) и нажмите Enter. Ответ должен быть таким:

```json
{
  "stored_in": "keychain",
  "apps_visible": 1
}
```

`stored_in` — название системного хранилища паролей вашей ОС (на Windows — `credential-manager`, на Linux — `secret-service`). Токен сохраняется там в зашифрованном виде; на диск в открытом виде он не пишется.

Проверка:

```bash
uv run appmetrica auth status
```

Должно быть `"valid": true`.

## Шаг 6. Узнать id приложения

```bash
uv run appmetrica apps
```

Ответ — список ваших приложений:

```json
[
  {
    "id": 123456,
    "name": "My Game",
    "time_zone_name": "Europe/Moscow"
  }
]
```

Запомните `id` — это число встречается во всех командах ниже. В примерах будем считать, что он равен `123456`; подставляйте свой.

## Шаг 7. Загрузить данные (sync)

```bash
uv run appmetrica sync --app 123456 --from 2026-08-01
```

Что происходит: инструмент просит у AppMetrica выгрузку сырых данных (события, установки, сессии, покупки) по дням, начиная с указанной даты. Выгрузка готовится на стороне AppMetrica — обычно от нескольких секунд до пары минут на день; прогресс печатается построчно. Ответ выглядит так:

```json
{
  "app_id": 123456,
  "from": "2026-08-01",
  "to": "2026-10-24",
  "fetched": [
    { "table": "events", "day": "2026-08-01", "rows": 51234 },
    ...
  ],
  "skipped_closed": 0,
  "error": null
}
```

Повторный запуск `sync` безопасен: уже загруженные «закрытые» дни пропускаются (`skipped_closed`), недостающие — дозагружаются. Дубликатов не бывает.

Если выгрузка «зависла» надолго — экспорты Logs API иногда идут медленно; прервите (`Ctrl+C`) и повторите позже, ничего не сломается.

## Шаг 8. Собрать базу аналитики (build)

```bash
uv run appmetrica build --app 123456
```

Из загруженных данных собирается локальная база, по которой считаются отчёты. Ответ — количество строк по таблицам:

```json
{
  "events": 1234567,
  "installations": 45678,
  "sessions_starts": 890123,
  "revenue_events": 2345,
  "ad_revenue_events": 6789
}
```

Порядок всегда один: изменили данные через `sync` → пересобрали через `build` → смотрите отчёты.

## Шаг 9. Первый отчёт

```bash
uv run appmetrica report --app 123456
```

Ответ — таблица по дням в JSON:

```json
[
  { "day": "2026-10-01", "dau": 1234, "sessions": 5678, "installs": 90 },
  { "day": "2026-10-02", "dau": 1250, "sessions": 5700, "installs": 85 }
]
```

- `dau` — сколько устройств было активно в этот день;
- `sessions` — сколько началось сессий;
- `installs` — сколько новых установок (без переустановок).

Диапазон можно ограничить: `--from 2026-10-01 --to 2026-10-07`.

## Другие отчёты

Все они работают по уже загруженным данным, токен не нужен:

```bash
# Retention: доля вернувшихся на 1-й и 7-й день после установки
uv run appmetrica retention --app 123456 --days 1,7

# Выручка: IAP в долларах по дням (конвертация по курсам ECB);
# при первом запуске скачается архив курсов (нужен интернет)
uv run appmetrica revenue --app 123456
# …и реклама: сырые суммы по валютам
uv run appmetrica revenue --app 123456 --ad

# Какие события вообще есть в данных (с объёмами)
uv run appmetrica events --app 123456
# Параметры конкретного события (например, какие уровни встречаются)
uv run appmetrica events --app 123456 --event level_start

# Воронка: сколько устройств дошло от первого события до второго.
# Окно (по умолчанию 7 дней) отсчитывается от первого шага.
uv run appmetrica funnel --app 123456 \
  --steps '[{"event_name": "tutorial_start"}, {"event_name": "first_purchase"}]' \
  --window 7d

# Свой SQL-запрос по локальной базе (только чтение,
# не больше 10 000 строк и 60 секунд)
uv run appmetrica sql --app 123456 "SELECT event_name, count(*) FROM events GROUP BY 1 ORDER BY 2 DESC"
```

## Где лежат данные и как их обновлять

Все локальные данные — в папке `~/.appmetrica-cli/apps/<id>/` (на Windows: `C:\Users\<вы>\.appmetrica-cli\apps\<id>\`): по одному файлу на таблицу и день плюс собранная база `analytics.duckdb`.

Обновление данных — всегда две команды:

```bash
uv run appmetrica sync --app 123456
uv run appmetrica build --app 123456
```

## Частые проблемы

- **«No AppMetrica token» (код 2)** — токен не сохранён: выполните шаг 5. На сервере без хранилища паролей задайте переменную `APPMETRICA_OAUTH_TOKEN` или `APPMETRICA_OAUTH_TOKEN_FILE` (файл с правами `chmod 600`) — детали в README.
- **Токен отклонён (`"valid": false`)** — проверьте, что токен скопирован целиком и у аккаунта есть доступ к приложению.
- **«analytics database has not been built»** — сначала `sync`, затем `build`.
- **Выгрузка долго висит на «Wait for result»** — экспорты Logs API иногда готовятся минуты; прервите и повторите позже.
- **`unknown table(s)`** — опечатка в `--tables`; допустимы: `events`, `installations`, `sessions_starts`, `revenue_events`, `ad_revenue_events`.
- **Хочу начать заново** — удалите папку `~/.appmetrica-cli/apps/<id>` и повторите sync/build.
